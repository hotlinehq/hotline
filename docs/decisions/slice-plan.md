# Slice plan, in full

The one line summary is in [memory.md](../../memory.md).

The proxy is built in small slices, tests first.

1. **Slice 1: done** (pull request #11). Forward proxy ingress, TLS to the vendor, integration ID, phase timings, the request record with redaction, OTLP output, the proxy's own errors, config loaded once. Scope and detail: [docs/proxy-slice-1.md](../proxy-slice-1.md).
2. **The `hotline-proxy` program: built** (commands, flags, stopping, exit codes, `@e2e` tests). Detail: [docs/proxy-program.md](../proxy-program.md).
3. **TLS from apps to the proxy: built** (`listen.tls`, renewal without a restart, Go cases 4 and 5 end to end). Detail: [docs/proxy-tls-from-apps.md](../proxy-tls-from-apps.md).
4. Still to come, roughly in this order:
   - the health checks `/livez` and `/readyz` on the admin port, with a short wait (`--drain-delay`, 5 seconds) before the proxy port closes on stop: built. Detail: [docs/proxy-health-checks.md](../proxy-health-checks.md);
   - the Node, Java and Rust clients in the end-to-end tests;
   - the vendor URL in path ingress: built, with refused calls recorded on every ingress. Detail: [docs/proxy-url-in-path.md](../proxy-url-in-path.md);
   - the guard against calls to internal addresses: built. Detail: [docs/proxy-internal-guard.md](../proxy-internal-guard.md);
   - the Host header ingress, with HTTP/2 from apps: built. Detail: [docs/proxy-host-header.md](../proxy-host-header.md);
   - each vendor api named once in the config, shared by integrations: built. Detail: [docs/proxy-spec-checks.md](../proxy-spec-checks.md), decisions 10 and 11;
   - checks of every part of a call against the spec (path, query, headers, cookies, body; and the reply's status, headers and body). Built. Detail: [docs/proxy-spec-checks.md](../proxy-spec-checks.md);
   - loading a large spec cheaply (Peter, 2026-11-01): a schema that is only a `$ref` reuses the shared shape's check, and a schema needing nothing else from the spec is built apart, once per text; SSM loads in 0.5 s and 300 MB instead of 1.3 s and 950 MB. Built. Detail: [docs/proxy-spec-checks.md](../proxy-spec-checks.md), details settled while building;
   - the transparent redirect ingress: built, as a Host header call with no proxy code change. Detail: [docs/proxy-transparent-redirect.md](../proxy-transparent-redirect.md);
   - AWS, starting with SQS: signed calls stay valid, actions as routes named by a header. Built 2026-10-30. Detail: [docs/proxy-aws.md](../proxy-aws.md);
   - the SQS invoice example: a string holding JSON (`contentMediaType` with `contentSchema`) is checked, AWS's JSON content type read as JSON where the spec marks it `x-hotline-body: json` (the proxy has nothing AWS-specific; Peter, 2026-10-30), the stable SQS spec made from AWS's Smithy model by `tools/aws-openapi`, one overlay per queue, and end-to-end tests with the example app. Built. Detail: [docs/proxy-sqs-example.md](../proxy-sqs-example.md);
   - XML bodies and S3, in one step driven by S3 in the invoice example (Peter, 2026-10-31). XML bodies for any vendor, read by the spec's shape and OpenAPI `xml` notes, then checked like JSON; `x-hotline-body` takes `json` or `xml`; a DOCTYPE is refused; namespaces are ignored. Routes picked by a query word after `#` (`/{Key+}#?tagging`), and `{name+}` takes the rest of the path, last part only. The stable S3 spec from AWS's Smithy model, with the bucket in the host name and `x-id` kept only where routes would clash. The example stores, fetches, lists and cleans up invoice PDFs in S3. Built. Detail: [docs/proxy-xml-bodies.md](../proxy-xml-bodies.md);
   - the shop example, step 1 (Peter, 2026-11-01): stable specs for DynamoDB, EventBridge, Kinesis, Secrets Manager, SSM, KMS, CloudWatch Logs and Step Functions; one api per AWS resource with its own overlay; base64 text holding JSON is decoded before its check (`contentEncoding: base64`, rule `base64`); AWS's Java patterns rewritten for Go by `tools/aws-openapi`, or kept as `x-aws-pattern` and not checked. Built. Detail: [docs/proxy-shop-example.md](../proxy-shop-example.md);
   - the shop example, step 3 (Peter, 2026-11-01): SNS and STS in AWS's query form (action in the form field `Action`), with `x-hotline-action-field` picking routes by a top-level body field once the body is whole, the reply check waiting for it, and the kept body grown from 1 MiB to 2 MiB; Lambda and SES v2 on AWS's REST and JSON form. Checkout publishes the unchanged invoice job on the `order-paid` topic; the invoices worker takes on the `invoice-worker` role, which covers all its calls, and gets the payment text from the `payment-qr` function; the mailer sends with SES from `MAIL_FROM`. No mark for dotted list names until a real example needs one. Built. Detail: [docs/proxy-aws-query.md](../proxy-aws-query.md), [docs/proxy-shop-example.md](../proxy-shop-example.md);
   - the CONNECT ingress, with interception: the proxy poses as the vendor inside the tunnel with certificates signed by the customer's issuer. Built. Detail: [docs/proxy-connect.md](../proxy-connect.md);
   - OTLP over HTTP, and TLS, login headers and gzip: built (gRPC removed on 2026-11-08). Detail: [docs/proxy-otlp-protocols.md](../proxy-otlp-protocols.md);
   - a level on every record (INFO, WARN for a spec problem or a 4xx, ERROR for a 5xx or a proxy failure), no body text, and resource labels per exporter (`resource`, values written out or from `env`/`file`; `service.name` and `service.instance.id` may change, `service.version` may not). Built 2026-10-30, for Grafana Cloud. Detail: [docs/otel-export.md](../otel-export.md);
   - a signature on every full record: HMAC-SHA256 with the integration's `fingerprintKey` over every attribute sorted by name plus the timestamp, no list of names, written as raw length-prefixed bytes with a type letter per value, not JSON (Peter, 2026-11-02) (`hotline.signature`, `hotline.signature_key_id`), and each body signed on its own as it passes (`hotline.request.body.signature`, `hotline.response.body.signature`), covered by the record's signature (Peter, 2026-10-31; replaces the RFC 9421 form of 2026-10-30). Detail: [docs/proxy-signatures.md](../proxy-signatures.md);
   - body fields in the record: a spec marks a body field `x-hotline-record: <attribute name>`, and the proxy copies its plain value (text cut at 256, number, true or false; never inside a list) into full records, signed, never into the counter. Names like the proxy's own are refused. The same mark on a call header (never a login header) copies the header as text. The SQS spec marks `QueueUrl` as `messaging.destination.name`, the full address, and lists `X-Amz-Target` on every action as `messaging.operation.name` (Peter, 2026-10-31). Built. Detail: [docs/proxy-body-fields.md](../proxy-body-fields.md);
   - overlays on an api's spec: OpenAPI Overlay 1.1 only, on the api only, applied at load in order, a target matching nothing is a warning, library `speakeasy-api/openapi/overlay`, plus the `hotline-proxy overlay` command that makes one from two specs (Peter, 2026-10-30). Built; needed by the SQS example. Detail: [docs/proxy-overlays.md](../proxy-overlays.md);
   - timings are whole microseconds, each name ending in `_us`, such as `hotline.timing.total_us` (Peter, 2026-10-31); since the trace, `total_us` is the only one left on the record. Detail: [docs/otel-export.md](../otel-export.md);
   - config reload without a restart: built. The files are checked every 5 seconds and SIGHUP reloads at once; certificates use the same check; listen addresses and exporters need a restart; `hotline.config.version` is the config file's name, `+` and a 12 character fingerprint. Detail: [docs/proxy-config-reload.md](../proxy-config-reload.md);
   - the proxy's own telemetry: metrics to the `telemetry` destination only, never split by integration, vendor, host, URL or route. Built. Detail: [docs/proxy-telemetry.md](../proxy-telemetry.md);
   - each call's timings as a trace, not number attributes (Peter, 2026-10-31): one trace per call to every exporter, no sampling; spans `hotline call` (from the app TLS handshake on a connection's first call), `app tls handshake`, `routing`, `vendor call` with `dns lookup`, `tcp connect`, `vendor tls handshake`, `send call`, `wait for vendor`, `receive reply`, then `reply to app` (failed when the app hangs up), and `request spec check` and `reply spec check`, each run alongside the call as soon as its side is whole (error when the spec is broken, ok when it passed). Only breakdowns fail spans, never the vendor's status. The record has `hotline.schema.status` valid, invalid or skipped. No data on both trace and record unless there is a good reason: the record keeps only `hotline.timing.total_us`; `hotline.connection.reused` and `dns.question.name` moved to spans. The trace is signed, in `hotline.trace.signature` on the record. Built (pull request #54, follow-up after it). Detail: [docs/proxy-traces.md](../proxy-traces.md);
   - the Docker image (Peter, 2026-11-01): Google's distroless static base, a static build with Go's own name lookup, `linux/amd64` and `linux/arm64`, no vendor specs in the image (they come with the config; Peter, 2026-11-02), `GOMEMLIMIT` set by hand in the examples, no health check command, releases are git tags (`v0.1.0` first), published to `ghcr.io/petercipov/hotline-proxy` with an SBOM, provenance and a cosign keyless signature. Built. A weekly clean-up keeps releases and `edge`, keeps the 5 newest `sha-` builds and deletes older ones (Peter, 2026-11-02). Detail: [docs/proxy-docker-image.md](../proxy-docker-image.md);
   - the load test, with k6. Spike and open questions: `load-test/requirements.md` in the project files (2026-11-02). Its first finding is fixed: the proxy copies bodies through 32 KB buffers borrowed from a shared pool, not a new buffer per call; `features/memory.feature` keeps it so (Peter, 2026-11-02). The copy of each body kept for the checks is also borrowed from a pool, in 8 sizes from 16 KB to 2 MiB, picked by `Content-Length`, and given back once the check has ended (Peter, 2026-11-02). Spec checks run on one worker per processor core; a check that finds every worker busy waits in a line whose body copies may take at most `specChecks.queueMemory` (64 MiB unless set, changeable on reload). When a new check does not fit, the oldest waiting ones are skipped as `overloaded`; nothing goes to disk. Detail in `docs/proxy-spec-checks.md` (Peter, 2026-11-02). Pipeline part one is `load/` (fakes, runner, `make load`, [load/README.md](../../load/README.md)): three unaveraged repeats per line, direct and through the proxy, alternating; the full job runs only on demand; results will be CI artifacts that automation reads from earlier runs; Grafana Cloud is left out for now. The proxy now sends `go.memory.allocated` so the load test can measure memory handed out per call (Peter, 2026-11-02).
